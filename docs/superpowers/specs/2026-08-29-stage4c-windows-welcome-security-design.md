# CareerPilot 精简版 Stage 4C-Windows 设计

> 历史记录（2026-09-05 统一标记）：正文保留当时的设计、任务和验收假设，不是当前执行指令。冲突内容已由[当前规则](../../../plan/CURRENT-POLICY.md)替代；按总体规划与新验收核对差距，不重做已完成阶段。

## 1. 目标

在当前 Stage 4B 与精简版 P0.5 基础上，选择性移植 PR13 的欢迎页和统一视觉，并补齐 Windows 本机使用所需的安全边界、一键启动与发布检查。

本阶段不恢复 PR13 的 Stage 5–7 业务功能。Docker、登录系统、HTTPS 证书、自动更新器和安装包制作不是取消，而是在核心功能完善后进入后续发布阶段。

## 2. 已确认的产品决策

- 每次打开应用默认进入 `#/welcome`，不保存首次访问状态。
- 欢迎页采用 PR13 的技术感方向：深蓝运行面板、蓝色主色、清晰标题和“进入工作台”按钮。
- 欢迎页只展示当前真实可用能力：申请追踪、163 邮箱同步、Excel 同步和多简历管理。
- 当前发布目标仅为 Windows 本机一键启动；Docker 延后。
- 当前安全范围为本机监听、受限跨域、Windows Credential Manager 和文件安全校验；不增加登录与会话系统。

## 3. 欢迎页与统一视觉

### 3.1 欢迎页

- 新增独立 `WelcomePage`，默认路由为 `#/welcome`。
- 主按钮进入 `#/overview`。
- 工作台左侧 CareerPilot 标志返回 `#/welcome`。
- 欢迎页不请求业务数据，因此后端不可用时仍能显示。
- 移除 PR13 中 Stage 6、JD 证据归档、自动化审批、外部集成等当前不存在的演示内容和文案。
- 不增加首次访问记录、动画框架或额外介绍页面。

### 3.2 工作台视觉

- 保持当前申请、邮件、Excel、简历、任务和设置页面的结构与行为。
- 统一主色、背景、字体层级、按钮、表单、卡片、状态标签和导航图标。
- 优先复用 PR13 已有 CSS 与当前依赖；不为视觉效果增加新的框架。
- 桌面端保持左侧导航；窄屏下保证导航、表单和表格仍可操作。

## 4. 选择性移植方式

- 选择性移植 PR13 的欢迎页结构、欢迎页样式、统一主题和已存在的图标依赖。
- 不整体合并 PR13 的 `App.tsx`、API 类型或数据库迁移。
- 在当前 `App.tsx` 中加入 `welcome` 路由和主题入口。
- 不引入 Agent、证据页、Gmail/Outlook、提醒、浏览器预填或 Stage 5–7 路由。

这种方式保留 PR13 的成熟视觉，同时避免把已删除或尚未确认的功能重新带回当前主版本。

## 5. Windows 本机启动

- 提供一个 Windows 启动入口，同时启动后端与前端并打开 `#/welcome`。
- 后端固定监听 `127.0.0.1:9998`，前端固定使用 `127.0.0.1:9999`。
- 启动前检查 Python 虚拟环境、Node 依赖和端口占用。
- 缺少依赖、端口冲突或进程启动失败时，输出明确且可执行的中文提示。
- 重复运行启动入口时识别已运行的服务，不重复创建冲突进程。
- 使用现有 Python、Node 和 PowerShell 能力，不制作新的启动器程序。

## 6. 必要安全边界

- API 仅监听 `127.0.0.1`，不向局域网或公网开放。
- CORS 只允许本机前端来源。
- 163 授权码和模型 API Key 继续存入 Windows Credential Manager。
- 密钥不得写入普通配置文件、日志、接口响应或 Git。
- 保留并验证上传文件的扩展名、大小、内容类型、伪造类型和路径边界检查。
- 启动失败不得修改数据库、Excel、简历文件或现有配置。
- 不因追求最小实现而削弱现有输入校验、数据备份或错误处理。

## 7. 错误处理

- 后端不可达时，前端继续使用现有页面错误提示，不吞掉异常。
- 欢迎页保持可访问，并允许用户看到产品入口；进入工作台后再显示后端连接错误。
- Windows 启动入口为依赖缺失、端口占用和启动失败分别给出提示。
- 发布检查失败时返回非零退出码，便于人工定位失败步骤。

## 8. 发布检查与验收

### 8.1 自动检查

- 后端全量测试通过。
- Python 静态检查通过。
- 前端 TypeScript 检查通过。
- 前端生产构建通过。
- 检查仓库未追踪密钥、运行数据和本机临时文件。

### 8.2 手动验收

- 每次打开默认进入欢迎页。
- “进入工作台”进入总览，品牌标志返回欢迎页。
- 欢迎页只描述当前真实功能。
- 申请、163 邮箱、Excel、简历、任务和设置功能行为不变。
- API 只能从本机访问，非允许来源被拒绝。
- Windows 一键启动可以重复执行，并识别已占用端口或已运行服务。
- 桌面与窄屏没有明显错位，交互控件可用。

## 9. 明确延后

以下能力在核心功能完善后单独设计和实现，本阶段不预建接口、抽象或依赖：

- Docker 与容器发布；
- 用户登录和会话认证；
- HTTPS 证书；
- 自动更新器；
- Windows 安装包；
- 云部署、多用户、PostgreSQL、对象存储和商业化能力。

## 10. 后续阶段

完成本阶段后，再单独设计 Stage 5 的 JD 与简历证据分析。Stage 6 仅在需要跨岗位、邮件、JD 和当前简历完成复合任务时引入受控单 Agent。Excel 同步、邮箱同步、简历存储、岗位修改和简历映射继续使用确定性代码。

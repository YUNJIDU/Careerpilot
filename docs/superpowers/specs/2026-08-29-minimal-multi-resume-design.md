# CareerPilot 最小多简历管理设计

> 历史记录（2026-09-05 统一标记）：正文保留当时的设计、任务和验收假设，不是当前执行指令。冲突内容已由[当前规则](../../../plan/CURRENT-POLICY.md)替代；按总体规划与新验收核对差距，不重做已完成阶段。

日期：2026-08-29

## 目标

在 `e82ea6d` 的本地 MVP 上选择性移植 PR13 的简历上传和安全文件处理能力，支持多份简历、手动版本归属和每个岗位一份当前简历，同时不引入归档、关联历史或 Stage 5–7 功能。

## 用户流程

简历页面只提供以下操作：

1. 查看已保存的简历及其版本。
2. 上传文件时手动选择“新建一份简历”或“作为已有简历的新版本”。
3. 选择一个简历版本，并把它设为一个或多个岗位的当前使用简历。
4. 查看或下载已保存的简历文件。
5. 确认后永久删除整份简历。

上传表单包含文件、名称、归属方式、已有简历下拉菜单和可选岗位。仅当归属方式为“新版本”时显示已有简历下拉菜单。系统不根据文件名或内容自动判断归属。

## 数据规则

- 一份简历可以包含多个由用户明确创建的版本。
- 每个岗位最多关联一个当前简历版本。
- 同一简历版本可以被多个岗位使用。
- 更换岗位的当前简历时直接覆盖原关联，不保存关联历史。
- 不提供归档、软删除、恢复或自动版本判断。
- 永久删除整份简历时，删除它的全部版本、实际文件和岗位关联。
- 删除正在使用的简历时，界面列出受影响岗位；用户确认后删除，并自动清空这些岗位的当前简历关联。

## 技术边界

从 PR13 选择性复用：

- 简历及版本的数据结构。
- 内容寻址文件保存。
- 文件大小、扩展名、MIME、文件签名、DOCX 宏、压缩结构和路径安全检查。
- 必要的上传、列表、下载和岗位关联服务逻辑。

不移植：

- 多邮箱、本地 `.eml` 和附件审批页面。
- 证据映射、公司研究、Agent、外部集成、提醒和浏览器预填。
- 关联历史、归档、恢复、自动推荐或自动简历匹配。
- PR13 的完整前端导航和视觉层。

Excel 双向同步继续使用现有 Stage 1–4B 实现，不新增简历字段或改变 Tracker Schema。

## 存储

- 简历元数据和岗位当前关联保存在固定数据目录内的 `careerpilot.db`。
- 简历文件保存在固定数据目录的 `resumes/`，使用内容哈希命名。
- 数据目录不得再依赖启动工作目录；实现时必须为现有 `careerpilot/data` 确定唯一、稳定的解析规则。
- 163 授权码继续保存在 Windows Credential Manager，不受本功能影响。

## API 与错误处理

只保留满足页面所需的接口：列表、上传、下载、设置岗位当前简历和永久删除。

- 非法或超限文件在写入数据库前拒绝。
- 新版本必须引用存在的简历。
- 岗位关联必须引用存在的岗位和简历版本。
- 删除操作必须带明确确认；服务端在一个事务中清空岗位关联并删除元数据。
- 文件删除失败时不得提交数据库删除，避免产生无法定位的残留文件。
- 重复内容可以作为同一简历的新版本被拒绝，并提示用户已存在相同文件。

## 最小验证

1. 上传文件并新建简历。
2. 手动选择已有简历并上传新版本。
3. 将一个版本关联到多个岗位。
4. 给岗位选择另一版本后，确认只保留一个当前关联。
5. 永久删除使用中的简历，确认文件、版本和关联全部消失。
6. 拒绝超限、伪造类型、带宏或路径不安全的文件。
7. 现有 163 邮箱、岗位、Summary 和 Excel 同步测试继续通过。

## 明确不做

- 简历归档、回收站和删除恢复。
- 岗位—简历关联历史。
- 自动判断新文件属于哪份简历。
- 自动选择岗位最合适的简历。
- 简历解析、评分、证据映射和训练建议。
- Gmail/Outlook、Stage 5–7 或其他非核心功能。

# CareerPilot Excel 唯一真源同步设计

> 历史记录（2026-09-05 统一标记）：正文保留当时的设计、任务和验收假设，不是当前执行指令。冲突内容已由[当前规则](../../../plan/CURRENT-POLICY.md)替代；按总体规划与新验收核对差距，不重做已完成阶段。

日期：2026-08-29

## 目标

把本地 `tracker.xlsx` 作为岗位数据唯一真源。每次从 Excel 导入都视为完整快照：新增行创建岗位，已有行完整覆盖看板，Excel 中缺失的岗位永久删除，并通过“当前简历”列维护每个岗位唯一的当前简历版本。

## 同步流程

导入必须按以下顺序执行：

1. 读取完整工作簿。
2. 校验所有岗位行、隐藏 ID、日期和当前简历引用。
3. 为没有 `_application_id` 的新行生成 ID。
4. 创建 Excel 新增岗位。
5. 用 Excel 值完整覆盖已有岗位，包括用空单元格清空字段。
6. 永久删除数据库中存在但 Excel 已不存在的岗位。
7. 更新每个岗位的当前简历映射。
8. 全部成功后一次提交；任何校验或写入失败都不修改数据库。

导入前创建数据库备份。备份是数据损失防护，不提供归档、回收站或产品内恢复功能。

## 岗位删除

当带 `_application_id` 的岗位行不再存在于 Excel 时，永久删除该岗位。

同时删除：

- 岗位主记录；
- 岗位时间线和字段来源；
- 岗位 Summary 版本；
- 岗位当前简历关联。

原始邮件记录不删除，只把 `application_id` 清空，以便邮件仍可审计或重新同步。简历及其版本文件不随岗位删除。

## 当前简历列

Tracker 增加可见列“当前简历”。填写方式：

- `后端开发简历`：使用该简历的最新版本；
- `后端开发简历@v2`：使用指定版本；
- 空白：清空该岗位的当前简历关联。

简历名称必须唯一匹配。名称不存在、同名无法确定、版本不存在或格式错误时，整次导入失败，并返回具体 Excel 行号和字段。

每个岗位最多关联一个当前简历版本；同一简历版本可以被多个岗位使用。变更映射时直接覆盖，不保存关联历史。

## 旧工作簿兼容

- 旧 Tracker 没有“当前简历”列时仍允许导入。
- 旧表导入不修改任何现有简历映射。
- 下一次导出自动加入“当前简历”列。
- `_application_id` 继续用于稳定识别岗位；新行没有 ID 时由系统生成。

## 覆盖规则

- Excel 单元格是岗位字段最终值。
- 空单元格会清空看板对应字段。
- 不再使用“Web 人工字段优先于 Excel”的冲突规则。
- `_row_version` 继续导出用于观察，但不阻止 Excel 覆盖。
- Web 修改仍可立即写入数据库；下次 Excel 导入时以 Excel 为准。
- 公司名称和岗位名称不能为空，否则整次导入失败。

## 事务与错误处理

- 完整解析和简历引用校验必须发生在写事务之前。
- 创建、覆盖、删除和简历映射在一个数据库事务内完成。
- 任一操作失败时回滚整次导入。
- 导入结果返回新增、更新、删除和简历映射数量。
- 页面明确提示此次操作会永久删除 Excel 中不存在的岗位，并要求用户确认。

## 最小验证

1. 新增 Excel 行后创建岗位。
2. 修改已有行后完整覆盖看板。
3. 清空单元格后看板字段同步清空。
4. 删除整行后永久删除岗位及其派生记录。
5. 删除岗位后原始邮件保留但解除关联，简历文件保留。
6. “简历名称”映射到最新版。
7. `名称@v版本` 映射到指定版本。
8. 空白“当前简历”清空关联。
9. 无效简历引用导致整次导入回滚。
10. 旧工作簿没有“当前简历”列时不改变现有映射。
11. 现有 163 邮箱同步、Excel 导出和简历永久删除测试继续通过。

## 明确不做

- 岗位归档、回收站或软删除。
- 岗位—简历关联历史。
- 自动判断岗位应该使用哪份简历。
- 同步多个 Excel 工作簿。
- 合并 Excel 与看板冲突。
- Stage 5–7 或其他非核心功能。

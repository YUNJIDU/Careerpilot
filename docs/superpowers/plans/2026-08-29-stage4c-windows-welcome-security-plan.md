# CareerPilot 精简版 Stage 4C-Windows 实施计划

## 目标

在不带回 PR13 Stage 5–7 功能的前提下，为当前本地 MVP 接入欢迎页、统一技术视觉、Windows 一键启动和最小发布检查，并验证现有本机安全边界没有回退。

## 实施原则

- 只从 `pr13-review` 复制被当前产品真实需要的视觉代码。
- 不整体合并 PR13 的 `App.tsx`、API、迁移或业务页面。
- 现有安全能力已经满足设计时，不重复实现。
- 每一步保持现有业务功能可运行，并在完成后执行最小相关检查。

## Task 1：接入真实能力版欢迎页

**修改文件**

- `frontend/src/WelcomePage.tsx`（新增）
- `frontend/src/welcome.css`（新增）
- `frontend/src/App.tsx`

**步骤**

1. 从 PR13 欢迎页提取顶部品牌、主标题、技术状态面板和进入工作台按钮。
2. 将展示内容改为当前真实能力：申请追踪、163 邮箱、Excel 同步和多简历管理。
3. 删除 Stage 6、JD 证据、自动审批、Gmail/Outlook 和外部集成文案。
4. 将默认路由从 `overview` 改为 `welcome`，并保留 `#/overview` 工作台入口。
5. 欢迎页独立渲染，不触发业务 API 请求。

**检查**

- 前端类型检查通过。
- 打开根地址进入 `#/welcome`。
- 后端停止时欢迎页仍可显示。

## Task 2：统一当前工作台视觉

**修改文件**

- `frontend/src/styles.css`
- `frontend/src/resume.css`（仅在现有规则与主题冲突时修改）
- `frontend/src/App.tsx`
- `frontend/package.json` 与锁文件（仅在最终确定复用 PR13 图标组件时修改）

**步骤**

1. 从 PR13 `app-theme.css` 中只提取颜色、排版、卡片、表单、按钮、状态和导航规则。
2. 合并到当前样式体系，不复制 Stage 5–7 专属选择器。
3. 统一导航图标的尺寸、间距和选中状态；优先复用当前符号，只有复用 PR13 图标能明显减少代码时才加入其单一依赖。
4. 将左侧品牌链接改为 `#/welcome`。
5. 保持所有表单字段、按钮行为、路由和业务文案不变。
6. 检查 800px 以下布局，确保导航可横向滚动、表格可滚动、表单保持可操作。

**检查**

- 前端类型检查和生产构建通过。
- 手动检查欢迎页、总览、申请、简历、邮箱、Excel、任务和设置页面。
- 对比修改前后 API 调用，不新增欢迎页业务请求。

## Task 3：补齐 Windows 一键启动

**新增文件**

- `start-careerpilot.ps1`

**可能修改**

- `README.md`

**步骤**

1. 使用 PowerShell 检查 `.venv\Scripts\python.exe`、`frontend\node_modules` 和必要项目路径。
2. 检查 `127.0.0.1:9998` 与 `127.0.0.1:9999`：
   - 两个服务都健康时只打开欢迎页；
   - 端口被非 CareerPilot 进程占用时停止并给出中文提示；
   - 服务未运行时分别启动后端与前端。
3. 后端固定使用 `127.0.0.1:9998`，前端继续使用现有 `npm run dev` 的严格端口配置。
4. 等待健康检查与前端地址可访问后，打开 `http://127.0.0.1:9999/#/welcome`。
5. 任一步失败时返回非零退出码，不修改业务数据。
6. 在 README 中只记录启动命令、常见错误和停止方式。

**检查**

- 首次运行能启动两个服务并打开欢迎页。
- 服务已运行时重复执行不会创建冲突进程。
- 模拟依赖缺失和端口冲突时显示明确错误并返回失败。

## Task 4：验证必要安全边界

**检查与按需修改文件**

- `backend/src/careerpilot/api.py`
- `backend/tests/test_stage0.py`
- `backend/tests/test_resumes.py`

**步骤**

1. 确认后端启动命令只监听 `127.0.0.1`。
2. 确认 CORS 只允许 `http://127.0.0.1:9999`，补一个拒绝非允许来源的回归断言（现有测试未覆盖时才增加）。
3. 运行现有 SecretStore 测试，确认密钥不回显、不写入普通设置文件。
4. 运行简历上传安全测试，确认扩展名、大小、内容类型和路径边界仍受保护。
5. 若以上能力已经通过，不修改生产安全代码。

**检查**

- Stage 0 安全测试通过。
- 简历测试通过。
- 手动检查 Git 状态，确认没有 `data/`、密钥或本机配置进入待提交文件。

## Task 5：增加最小发布检查入口

**新增文件**

- `check-release.ps1`

**步骤**

1. 顺序执行后端全量测试、Ruff、前端 TypeScript 检查和生产构建。
2. 任一命令失败立即返回非零退出码并保留原始输出。
3. 不加入 Docker 构建、安装包、自动更新或部署步骤。
4. 在 README 中记录发布检查命令。

**检查**

- 故意制造一个失败命令时脚本返回失败；恢复后全套检查通过。

## Task 6：完整回归与交付核对

**步骤**

1. 运行 `check-release.ps1`。
2. 使用 `start-careerpilot.ps1` 启动应用。
3. 手动检查欢迎页与全部现有工作台页面。
4. 验证 Excel 导入仍以 Excel 为唯一真源，并刷新岗位与简历映射。
5. 验证 163 邮箱测试与同步入口未变化。
6. 验证多简历上传、当前简历关联和永久删除未变化。
7. 检查提交差异，只包含本阶段文件，不包含 PR13 Stage 5–7 代码或运行数据。

## 明确不在本次实施中

- Docker 与容器发布；
- 登录、会话和多用户；
- HTTPS 证书；
- 自动更新器和 Windows 安装包；
- Stage 5 证据智能；
- Stage 6 Agent；
- Stage 7 Gmail/Outlook、提醒和浏览器预填。

这些能力在核心功能完善后按独立设计推进，本计划不为其预建代码。

## 4. 真实模型兼容性修正

真实模型回归发现并修正两个不扩大功能范围的问题：

1. 模型在 `tool` 动作中同时返回了只对 `final` 有意义的占位字段。服务端现在根据动作分支忽略非活动分支占位内容，但仍严格校验当前分支。
2. 模型在只读工具参数中重复提供了当前 Run 已绑定的 `application_id`。服务端允许并移除完全相同的冗余 ID；不同 ID、额外参数和跨岗位访问仍立即失败。

两项都增加了回归覆盖，没有放宽工具白名单、写入权限或岗位隔离。

## 5. Multi-Agent 决策

决定：**不引入 Multi-Agent**。

证据：

- 真实验收任务仅需 1–2 个串行工具，在 2–3 次模型调用内完成。
- 未观察到三个以上可以独立并行、又必须由不同上下文负责的专业分支。
- 当前错误来自模型输出兼容性，可用严格 Schema 和普通工具适配解决，不是单 Agent 的路由瓶颈。
- 现有确定性 Service 可脱离 Agent 独立运行；拆成多个 Agent 会增加权限面、Prompt Injection 通道、预算、审计和恢复复杂度，却没有测得收益。

只有以下条件同时出现时才重新提交 Multi-Agent 详细设计：

1. 真实任务稳定存在三个以上独立专业分支；
2. 单 Agent 在合理预算内仍因上下文、路由或时延无法达到门禁；
3. 增加确定性工作流或一个普通白名单工具不能更简单地解决。

因此 Stage 7 应继续以已验证的单 Agent 和独立 Service 为基础，不预建多 Agent 空壳。

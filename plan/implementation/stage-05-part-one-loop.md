## 本轮结果（2026-09-05，工作分支，尚未发布）

本轮按“底座回归 → 失败场景修复 → JD 纵向切片 → 浏览器检查”执行。后端从 49 项扩展为 64 项全部通过；`ruff check backend`、前端 `npm run check`、`npm run build` 通过。仍有原有 Starlette/httpx 弃用提示，不影响本次测试。

新增底座测试 10 项，覆盖删除后重放、旧事件不能回退、字段增量与无变化幂等、同公司岗位歧义、手工字段冲突、外部 Excel 修改保护、断网/进程重建恢复、模拟文件占用导致导出失败、未导出期间阻止导入、人工关联以及 Web 写回失败恢复（部分合并在同一场景）。生产行为已修复，旧测试中与新版规则冲突的“按最近投递猜测岗位”“空同步回填旧日期”预期同步修正。

恢复规则：数据库暂存尚未写回的更新，持久化原 Excel 指纹；相同文件可重试同步或导出，期间禁止导入与继续编辑。若文件也被外部修改，保留两边、拒绝覆盖，需人工核对；本轮未实现两份数据的自动冲突合并。文件占用通过 PermissionError 模拟，未把真实桌面 Excel 锁文件行为计为通过。

歧义邮件提供列表、提取字段和手动关联入口；关联只保存证据，不自动覆盖岗位字段。用户在详情中核对后补充。删除岗位后的邮件保留删除标记，不能再次自动或手工恢复旧关联。专属 Summary/JD 检查点随岗位删除清理。

## Stage 5 第一组已启动：JD 首个可运行交付

岗位详情 → 粘贴完整 JD → 确认向配置模型发送 → 要求/重要性/明确或推断/原文引文/理由/未知项 → 刷新后仍可查看。无需 Brave 配置。保存 JD 原文及哈希、模型名、提示版本；相同岗位、JD、模型地址/名称与提示版本复用已有结果，失败可在表单重试。重要性调用只传 JD，不传简历或个人字段，不产生匹配分数。

新增 5 项 JD 测试（包含参数化用例）：引文必须出现在原文、推断不能为 critical/high、非法枚举拒绝、失败不发布且可重试、输入不包含简历、跨重启持久化、岗位删除清理、API 外发确认。浏览器使用独立临时数据库和合成模型，通过未确认禁用、生成、引文呈现与刷新持久化；未调用真实邮箱/付费模型。

此切片独立实现通用 JD 结构与约束，没有复制上游实质性 Prompt/代码；正式复用上游内容仍须固定 commit、文件及许可。

## 下一轮顺序与门槛

1. 在同一 JD 产物上完善职责/技能/学历/地点/工作授权等分类，加入投递简历事实与原文映射；固定简历版本，保持 JD 重要性不随简历变化。
2. 扩展共用研究与 Summary 4B+：业务、文化、薪资/市场、流程、考核主题、来源等级与时效；不知道面试类型时仍尽可能完整，缺可靠来源则标未知。
3. 按 EVALUATION 建立固定回归与留出集，真实模型运行并人工标注覆盖率和事实支持率；通过后再把第一组标为完整交付，之后进入 A–G。

64 项程序测试不等于 30 个产品回归样本 + 20 个留出样本，也不能证明 JD 语义完整性或模型正确率。简历事实、证据映射、研究增强、真实模型质量、Windows CMD 启停与真实邮件验收仍未在本轮完成。当前是第一组的起点，不是 Stage 5 第一组全部完成。

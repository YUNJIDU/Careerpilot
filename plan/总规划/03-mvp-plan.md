# CareerPilot 总体规划与实施顺序

更新：2026-09-05。状态：已确认产品规划，不等于功能验收报告。
依据：[当前产品规则](../CURRENT-POLICY.md)。协作：[Harness](../stages/stage-06-agent-orchestration.md)。放行：[统一评测](../EVALUATION.md)。

## 产品与用户

为本人及能本地部署的技术用户提供求职记录、公开研究、岗位判断、简历建议与面试准备。Windows 本地 Web 为入口，单用户、163 邮箱、多份简历。用户负责求职决定及外部提交，系统提供证据和直观评分。
Excel 是个人岗位数据库及岗位字段唯一事实源；Web 编辑安全回写 Excel。数据库保存运行副本、邮件证据、任务、研究与准备成果；Markdown 展示岗位详情和分析。

## 用户闭环

手工/Excel 创建岗位 → 手动同步只读邮件 → 按字段补充新事件 → 查看岗位、来源和投递简历 → 主动生成共享研究与 A–G → 阅读建议和分数 → 按需简历建议或全面面试准备 → 文字模拟与反馈。
没有邮件也能手工维护 JD 和岗位；短信等不增加专用同步。当前简历就是当时投递简历。

## 数据规则

Excel 完整导入的缺行永久删除岗位及专属派生记录，空值明确清空；展示删除影响并确认，保留既有导入备份措施，不新增归档/回收站。原始邮件解除关联、独立简历保留。
同步前读取 Excel 基线：无新信息不动，明确较新事件仅修改涉及字段；缺岗位名不清空手工岗位；旧邮件不覆盖新事件。与手工补充先后不明时保留当前值并提示字段冲突。
同公司多岗位需可靠关联，歧义不只按最近时间强配。重复邮件/旧记忆不能恢复已删除岗位。Web 写回前遇到未导入 Excel 改动先提示，不静默覆盖。

## 求职智能范围

保留 Stage 5 原四组和 A–G：A 岗位概述，B 简历匹配，C 级别策略，D 公司/薪资/市场，E 简历优化重点，F 准备方向，G 真实性风险。维持五维综合判断和 1–5 总分，G 不计分，不另建加权评分体系；缺关键输入时不制造精确分数。
近期吸收 career-ops 的 B 要求重要性/证据标注、公司研究与面试流程、低成本模型对比方法。先看 JD 判重要性，再看简历判匹配；推断不能冒充明确要求，重要性列不改总分。
共用 JD、证据映射和公司资料。Summary 给情报，F 给重点，Interview 给清单与练习；E 给重点，Resume 展开建议。Resume 默认不产替换文本，用户追问时才按证据与模型能力提供示例。
面试类型可能未知，准备默认全面覆盖公司业务/文化、市场薪资、岗位技术、个人经历、行为问题和反问。复用或补齐完整 A–G 背景，无需用户先手动运行另一个入口；查不到的信息标未知并继续其他内容。先清单与故事映射，再一次完整文字模拟。

## 后续实施顺序与交付证据

| 顺序 | 工作 | 输出与放行条件 |
|---|---|---|
| 1 | 核对现有底座与 Windows 体验 | 邮件字段增量、人工短信补充、歧义关联、Excel 编辑/删除/写回、简历和启动场景；记录失败后局部修复 |
| 2 | 建立评测基线与上游取用清单 | 脱敏回归/独立验收样本、模型与预算记录；正式移植前固定上游 commit、文件和许可，不用浮动 main |
| 3 | Stage 4B+ / Stage 5 第一组 | 共享研究、JD 重要性、简历事实与映射；只交付一次情报基础，通过来源与关键要求覆盖验收 |
| 4 | Stage 5 第二组 | 完整 A–G、有据建议和直观分数；判断合理性、信息不足和重复运行稳定性通过 |
| 5 | Stage 5 第三组 | 默认建议、追问措辞边界；不编造、不修改原简历，各声明支持模型独立验收 |
| 6 | Stage 5 第四组 | 全面清单与故事映射先可用，再文字模拟/反馈；未知面试类型、无薪资等场景通过 |
| 7 | Stage 6 | Orchestrator 工具/记忆/Agent 调度、成果复用、权限、取消与恢复；多 Agent 只逐个按收益加入 |
| 8 | Stage 7 | 提醒/日历/通知、受控预填和回复草稿，分别验收；新增申请材料候选需另定范围 |
| 9 | Stage 8 | 核心稳定后的本地发布，再另行设计云端产品与商业化；不提前加入云基础设施 |

以上是依赖顺序，不新增 5A–5E 产品拆分；每组有独立验收证据，A–G 本身不拆。工具与上下文边界在 Stage 5 就遵循 Harness，统一用户入口在 Stage 6 交付。

## 后续候选与排除范围

H 申请回答、求职信、申请邮件、谈薪/Offer、复盘统计列为后续模块，不是当前 Stage 5 必须完成项。H 如启用由用户主动请求，不机械套用 4.5 分门槛。具体见[上游取用策略](01-open-source-reference.md)及[长期候选](02-long-term-vision.md)。
当前不做岗位扫描/推荐/融资公司发现、自动定制简历或 PDF、任意插件生态、另一套 Tracker、自动发信投递或提交、验证码绕过、多邮箱及常驻监控。

## 验收与维护

按统一评测记录分子分母、样本/模型/提示词版本、预算、失败场景和人工判断。硬性数据与事实门槛不得用平均分抵消。上游模型一致性只作辅助，不能替代本项目真实功能验收。
最新用户决定 → 当前规则 → 本总规划/当前 Stage → 历史设计。需求变化同步更新这四处及验收；历史文件保留时必须明确非当前指令。代码能力、计划目标和实测通过分别表述。

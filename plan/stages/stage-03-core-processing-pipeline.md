# Stage 3：邮箱同步与客观信息提取

## 目标

跑通“用户触发同步 → 只读获取邮件 → 提取客观求职信息 → 保存证据 → 更新 Application 与 Excel”。

系统不替用户盯邮箱、理解全部事件或做求职决策。默认用户已经查看并了解自己的邮件。

## 输入

- 本地 `.eml`、`.json` 邮件样本。
- 163 邮箱收件箱指定时间范围。
- 现有 Applications。

## WBS

### 3.1 MailAdapter

- 定义供应商无关的邮箱接口。
- 实现本地样本适配器。
- 实现 163 IMAP 只读适配器。
- 保留 Gmail/Outlook 后续扩展边界。

### 3.2 同步方式

- 本地 Web 手动同步。
- 可选本地定时同步，默认关闭。
- 同步游标、时间窗口、超时、重试和限速。
- 失败不推进游标，重复同步不重复写记录。
- 每次同步生成 `job_id`，按成功提交的单封邮件推进检查点。
- 中断后可从最后成功邮件继续，也可重新开始而不制造重复数据。

### 3.3 读取与保存

- 从收件箱指定时间范围读取。
- 邮件头和规则低成本初筛。
- 候选求职邮件再读取和清洗正文。
- 长期保存元数据、结构化结果、必要摘要、证据片段和原始哈希。
- 默认不长期保存完整 MIME 和完整正文。

### 3.4 客观信息提取

提取：

- 公司、岗位和投递信息。
- 简历筛选、测评、笔试和面试安排。
- 一面、二面、三面、HR 面和终面。
- 日期、时间、截止时间、链接、明确结果和要求。

不明确的信息留空。不得生成行动建议，不得替用户接受、拒绝、撤回或判断岗位价值。

### 3.5 Application 关联与 Tracker 更新

- 关联已有 Application 或建立新的岗位记录。
- 保存邮件来源和证据片段。
- 追加邮件时间线。
- 更新数据库统计快照并同步 Excel。
- 用户在 Excel 中的手工值优先，不被静默覆盖。

### 3.6 附件

- 检测疑似承载 JD、笔试或面试必要信息的附件。
- 默认提示用户确认后下载。
- 预留白名单自动下载配置，默认关闭。
- 文件类型和大小限制。
- 禁止执行宏、脚本和压缩包内容。
- 保存来源邮件、哈希、下载时间、本地路径和 Application 关系。

## 安全

- 邮箱只读。
- 邮件和附件均视为不可信输入。
- 邮件内容不能修改系统指令或触发外部操作。
- 凭证只存环境变量或系统密钥库。
- 日志和证据片段按最小必要原则保存。
- 解析失败隔离单封邮件，不阻塞批次。

## 完成标准

1. 本地样本和 163 邮箱使用同一业务接口。
2. 用户能在本地 Web 手动同步。
3. 可选定时同步默认关闭。
4. 同一邮件重复同步不会重复写数据。
5. 客观信息能写入数据库和 Excel。
6. 所有提取信息可回溯邮件来源和证据片段。
7. 必要附件可安全下载并关联岗位。
8. 邮箱或单封邮件失败不会破坏已有数据。
9. 本地 Web 能显示已处理数量、停止位置、失败原因和恢复建议。

## 开源参考

- [codefuturist/email-mcp](https://github.com/codefuturist/email-mcp)：统一 IMAP 邮件对象、多账户、搜索和同步边界参考；首发不因此引入 MCP。
- [Python `imaplib`](https://github.com/python/cpython/blob/main/Lib/imaplib.py) 与 [`email`](https://github.com/python/cpython/tree/main/Lib/email)：163 IMAP 只读获取和 MIME 解析的优先基础。
- [microsoft/markitdown](https://github.com/microsoft/markitdown)：必要 PDF/DOCX 附件转 Markdown 的候选参考；其安全说明强调最小文件访问权限，正式采用前需针对不可信附件做沙箱和格式白名单评估。

本 Stage 不直接复制任何项目的数据写入逻辑，所有提取结果仍通过 CareerPilot Application Core。

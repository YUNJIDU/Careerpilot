# Stage 6：Career Assistant 与 Harness

更新时间：2026-09-05。产品依据：[当前规则](../CURRENT-POLICY.md)。本设计为后续交付目标，不代表当前代码已有完整 Agent 系统。

## 目标与协作方式

采用中心 Orchestrator 管理专业模块与后续专用 Agent。用户只需指定岗位和目标，系统负责工具、上下文、依赖、权限、预算、恢复和汇总。Stage 5 原四组能力保持可独立使用。
最初一个 Career Assistant 调用稳定模块即可；独立 Agent 可逐个加入，用同一评测集证明收益，不要求一次搭建全部角色或自由角色会议。

## 工具调度

每个工具声明用途、输入/输出、岗位范围、读取资料、外部调用、修改影响和失败行为。只允许已注册工具，不允许任意 Shell、SQL、代码或文件路径。
流程：确认用户目标与岗位 → 读取必要事实/已有成果 → 检查缺口与有效性 → 选择工具和依赖顺序 → 执行并检查结果 → 保存或展示。
查询、Excel 同步、日期计算使用确定性工具；理解、公开研究与建议使用模型能力。工具输出保留来源、输入版本、任务状态与错误，不把外部文本作为调度指令。
每次任务设定调用、重试、时间和成本上限；失败仅重试必要步骤，保留有效成果；支持停止、恢复和取消。每种任务的具体预算在首次验收前固定并记录。
一次用户授权覆盖已展示的数据范围、外部调用、预算和报告保存；不逐步重复确认。新增外部操作、扩大数据范围、超出批准预算或改变岗位事实需要新的明确授权。授权恢复不重复产生副作用。
邮箱同步不自动启动研究、评估或训练。Agent 修改岗位只能通过遵循 Excel 规则的受控服务，不能直接写数据库或工作簿。

## 记忆管理

| 类别 | 内容 | 所有权和生命周期 |
|---|---|---|
| 岗位事实 | Excel 岗位字段、投递简历关联 | Excel 为真源；手工补充和邮件字段更新遵循当前规则 |
| 研究成果 | JD、公司文化/业务、市场、招聘流程、来源 | 共享成果按来源时间、适用公司/岗位、输入版本复用；失效项按需更新 |
| 用户资料 | 简历证据、用户确认的故事和偏好 | 用户可查看、更正、删除；模型猜测不能自动保存为事实 |
| 任务状态 | 目标、步骤、结果引用、预算、审批 | 用于暂停恢复；完成后仅保留必要记录，不自动成为长期个人记忆 |

只向 Agent 提供当前任务必要数据；不同岗位的私人上下文隔离。公司公共研究可共享，但岗位匹配与个人故事不能随之跨岗位混入。
简历/JD/用户事实改变后标记相关旧分析待更新，不静默改写历史报告。报告保存所用版本。删除岗位清除专属成果与记忆，不借旧缓存恢复岗位；独立简历、用户主动维护的故事库和共用公司资料按各自归属保留。
凭证、无关完整邮件正文、未经证实的经历与拒绝原因不进入记忆。不预先引入向量数据库或独立记忆平台。

## Agent 职责与依赖

| 角色 | 负责 | 不负责 |
|---|---|---|
| Orchestrator | 目标、范围、路由、预算、授权、依赖、汇总 | 另建一套岗位事实或评分规则 |
| Research | 公司/JD/市场/文化/流程/考点及来源 | 个人匹配评价 |
| Evaluation | 既有 A–G 综合分析与 1–5 分建议 | 重复维护公司事实或创造个人经历 |
| Resume | 基于证据的修改建议；追问后才给措辞示例 | 自动改简历或默认生成替换全文 |
| Interview | 全面准备清单、故事映射、文字模拟及反馈 | 猜测面试类型并删减研究范围 |
| Reviewer | 事实、引用、证据等级、安全和一致性 | 独立重做整份研究与评分 |

独立的公司研究和简历事实整理可并行；评估等待相关证据，准备复用或补齐完整 A–G 背景。信息不足标记未知，不阻塞可完成部分。
交接使用结构化成果与引用，不共享无限聊天上下文。相同研究只执行一次并复用；结果冲突回到原来源，不能投票制造事实。复核失败回到相关步骤，在任务预算内修正；仍失败则交付明确标注的部分结果。
研究只有最小公开访问权限，专业角色只读必要岗位上下文。高风险工具不因 Orchestrator 委派而获得额外权限。

## 验收

按 [统一评测设计](../EVALUATION.md) 检查路由、岗位隔离、记忆失效、授权、预算、取消恢复、结果复用和完整背景覆盖。多 Agent 与单 Assistant 使用相同输入、模型版本及预算口径比较质量、错误、P95 耗时和成本，不以 Agent 数量作为完成标准。

# 统一功能验收与模型评测

版本：2026-09-05。依据：[当前规则](CURRENT-POLICY.md)、[Stage 5](stages/stage-05-career-intelligence-modules.md)、[Harness](stages/stage-06-agent-orchestration.md)。以下是发布目标，不是已取得的实测结果。

## 范围和样本

保留 Stage 5 原四组，不重做 career-ops 业务评分。业务 1–5 分与本文件的质量评测分开：评测检查判断合理性、证据和稳定性，不训练模型迎合固定岗位分数。
初始固定回归集至少 30 个脱敏场景，独立验收集至少 20 个；每项指标必须报告样本量和分子/分母。可重叠覆盖：Excel/邮件、JD/简历、研究/A–G、建议/面试、Harness 各至少 5 个场景。验收集不能用于调提示词；样本增长后保持历史回归覆盖。
困难场景必须包括：同公司多岗位且无岗位名、短信手改、旧邮件、新邮件只改一字段、Excel 未导入编辑、永久删除后重同步、简历版本变化、未知面试类型、无薪资来源、来源冲突、低能力模型、用户追问措辞、越权诱导、取消与恢复。
模型比较冻结 JD/简历/网页材料、提示词、工具配置与预算，每个模型独立报告。联网研究另测新鲜度与访问失败，不把网页变化归因为模型不稳定。

## 指标与初始门槛

| 对象 | 计算口径 | 放行目标 |
|---|---|---|
| 字段更新 | 预期字段变化与实际变化逐项比对 | 无关字段覆盖、重复记录、旧事件覆盖新值、未同步却报成功均为 0；固定场景全部通过 |
| 岗位关联 | 自动正确关联/全部自动关联；正确自动关联/可明确关联样本 | 精确率 ≥95%，覆盖率 ≥90%；歧义强行关联为 0；另报待关联率 |
| JD/简历证据 | 有有效证据的引用/全部引用；识别关键要求/人工标注关键要求 | 引用有效率 100%，关键要求覆盖 ≥95%，虚构个人事实为 0 |
| 公开研究 | 有可定位来源的外部事实/全部外部事实；来源支持的抽检结论/抽检结论 | 可追溯率 100%，支持率 ≥95%；来源不存在、冲突或过期必须标注 |
| A–G | 全章节覆盖、判断人工量表、同输入 3 次运行分数极差 | 章节检查通过；合理性均分 ≥4/5；有足够信息的同输入分数极差 ≤0.5/5；关键事实无矛盾 |
| 简历建议 | 默认输出范围、证据依据、人工可用性 | 默认不输出替换文本；每项建议关联依据；可用性均分 ≥4/5；追问措辞不得引入虚构事实 |
| 面试准备 | 公司业务/文化、市场薪资、岗位技能、个人经历、行为与反问逐类检查 | 每类有有据内容或明确缺口，覆盖 100%；JD 关键要求准备覆盖 ≥90%；未知面试类型不能删减类别 |
| 故事/文字模拟 | 故事证据，开始→问答→结束→反馈流程，量表理由 | 不虚构个人故事；端到端场景全部通过；每项反馈对应回答内容或缺失项 |
| Harness | 正确任务路由/全部路由场景；权限、恢复、缓存失效和取消用例 | 路由 ≥95%；越权、串岗位、删除后记忆复活、重复副作用、取消确认后新增写入为 0 |
| 效率 | 成功率、调用数、成本、耗时中位数/P95 | 按任务和模型报告；不得超过已批准任务预算；超时返回可解释的部分结果 |

“无资料”只在记录检索尝试、失败原因或现有资料缺口后成立，不能靠把所有项标未知达标。另报已获证据类别/全部类别和任务完成率，人工检查是否进行了合理完整的研究。个别资料未知允许继续准备，不等于整体任务验收合格。
人工量表：1=事实错误或不可用，2=明显缺漏，3=基本可用但需较多修正，4=有据且可直接指导下一步，5=完整清晰、无需实质修正。A–G 重点评判断与证据，简历/面试重点评针对性和可操作性；不评是否生成华丽替换文本。
初次验收人工查看全部智能报告；稳定后仍人工检查全部失败/边界场景及至少 20% 普通样本。模型裁判仅作辅助，不能独自决定通过。若多人评分有分歧，记录理由并复核，不掩盖分歧。

## 评分与信息不足

保留既有 A–G、五维整体判断、1–5 分和现有建议阈值，不另加权重公式；G 风险独立展示、不计总分。分数不是录用概率。
缺薪资等局部信息时正常展示判断并标明限制；缺 JD 或简历等关键输入以致无法形成有依据的匹配判断时，显示信息不足并列出需要补充的材料，不给伪精确分数。面试其余背景资料仍可整理。

## 放行与模型能力

四组分别记录可运行交付结果，不改动 A–G 的内容结构。准备清单与故事映射先验收，再验收一次完整文字模拟；不引入额外独立产品阶段。
硬性数据安全和事实门槛任一失败即阻止对应能力发布。比例指标不达标则修复后重跑受影响集及固定回归；未经实测不得写“已通过”。阈值调整必须说明原因并更新版本，不能为一次失败临时降低。
每个被声明支持的模型单独通过；能力不足时限制为已验证能力并明确告知，不默认声称所有模型都可生成可靠措辞或稳定评分。
任务成本/时间预算在首轮基线测量后、正式验收前固定；以后对同任务比较成功率、质量、P95、成本。多 Agent 只有在硬门槛通过且有记录的质量或效率收益时替代原流程，否则保留简单调度。

## 验收记录

每次记录提交号、模型/提示词/样本版本、预算、成功失败数量、各项分子分母、人工评分与理由、耗时/成本、未通过场景和结论。原始真实邮件/简历不得进入 Git；提交脱敏用例与汇总证据。当前本次只更新设计，尚未建立或运行这套评测集。

## 上游复用的补充验收

- B 的重要性：固定 JD、替换强弱不同简历，要求的重要性与 JD 依据不得随候选人改变；单独统计违反次数，固定场景必须为 0。
- 推断不能标成 JD 明确要求或 critical/high；来源分级错误为 0。重要性列不得被加入综合分公式，保持原有五维整体判断。
- 公司研究/准备流程移植后仍需覆盖未知面试类型和资料缺失，不能用上游示例替代本项目 JD/简历。
- 上游 golden-set 方法作为模型选择辅助：冻结输入与参考版本，报告候选模型的岗位类型一致率、分数差异及成本；参考模型输出不是人工真值，不能单独决定发布。
- 不直接继承上游六类岗位分类或 10 个合成案例作为本项目完整覆盖；按实际岗位样本检查适用性。保留本文件既有回归集、独立验收集、人工抽检与硬性门槛。
